## Identity, projection and absence semantics

Strictly parse JSON without duplicate keys/nonfinite values. A successful response must be a list of the exact frozen query count, each member null or a record. Validate requested field types before projecting: paperId is a forty-hex string; externalIds is an object-or-null; matching keys DOI, ArXiv, PubMed and PubMedCentral have string-or-null values, while unknown namespaces are ignored subject to general JSON bounds; title/abstract/publicationDate are string-or-null; year is integer-or-null (excluding booleans); authors is a list of objects with string-or-null names; publicationTypes is a list of strings; journal is object-or-null with string-or-null name and optional scalar volume/pages. Unknown provider fields are ignored. Bound nesting to sixteen levels, each record to 256,000 UTF-8 bytes and each provider list to 10,000 entries before projection; violations make the whole response incomplete. Response size is enforced while reading, before parsing. Null/no matching validated identity remains unresolved, not evidence of absence of a paper. Do not trust list position alone: attach records only when their paperId equals a requested S2 ID, or an external identifier matches that query's normalized DOI/arXiv base/PMID/PMCID. Use only documented externalIds keys DOI, ArXiv, PubMed and PubMedCentral, normalized with the same URL-query rules; unknown keys do not match. PMID/PMCID numeric strings normalize leading zeros consistently, while an empty numeric identifier is invalid. Validate the forty-hex paperId case-insensitively and preserve the provider spelling in diagnostics. No title-based identity. Preserve explicit cross-identifiers as provider-reported relations, not proven quality or independently verified identity. Multiple returned records that claim one query ID with conflicting paperIds make that query conflicted/unknown; do not select a winner. Repeated records for the same paperId must have identical requested-field projections; otherwise that query is conflicted/unknown. Records with no matching requested identity are retained only as unmatched counts; they never attach by position. Each card uses its selected query identifier only, even if an unmatched alternate anchor could return metadata. A malformed whole response makes the acquisition incomplete without partial acceptance or retry.

Keep original card fields unchanged. Add a separate metadata record with status, requested identifier/scope, reported-by Semantic Scholar Graph, capture time, paperId, validated reported identifiers, reported title, date/year, journal, publication types, author names and a bounded abstract excerpt when present. Preserve missing/null/conflicting fields explicitly as unknown. Original per-engine capture provenance remains unknown; this later lookup is new provenance, never reconstructed historical provenance. Record full raw response SHA-256/length privately and publish only the allowlisted, sanitized projection. No raw response or credentials in the repository.

The public abstract excerpt is the first at most 128 whitespace-delimited words and at most 768 Unicode characters; report whether clipped and the original abstract length/hash. Limit author names to the first 32 (each at most 160 characters), type labels to the first 16 (each at most 80 characters), and bounded textual fields to 512 characters with explicit clipping flags. Report original counts for clipped lists. Never call reported publication types peer-review proof, label a JournalArticle as primary research, or treat citation counts/indexing/venue as authority. Citation counts, recommendations, author profiles, emails, references, full articles and AI-generated summaries are not requested or projected. Authority, usefulness and whether a method works remain unverified. No new grouping or ranked-order decision occurs.
