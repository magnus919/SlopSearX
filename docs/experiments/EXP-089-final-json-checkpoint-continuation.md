# EXP-089 — preserve the card checkpoint and receive final JSON directly

Status: prospective registration; no live stage admitted.

EXP-088 completed every required card assessment, then stopped when the first source assessor’s output-writing script failed. Its [terminal outcome](evidence/EXP-088/completed/readout.md) remains assessment-inconclusive. This stage fixes the response carrier: the controller stores and hashes the assessor’s actual final-message bytes, then applies unchanged reference and coverage validation. It never treats a completion assertion as a response or reconstructs grades from a failed script. Missing, malformed, mismatched or oversized output is terminal, without retry or repair.

All sixteen validated EXP-088 card assessments are carried forward as a complete, immutable A/B development reference set. Every assigned input, original catalog, label binding, raw and decoded response, verification and provenance receipt is pinned and reverified. No case or assessment is selected by its grades; no ranking or quality analysis has used these references. The same tasks, cards, evidence, rubric, candidate and numerical gates remain fixed. This is declared reuse, not fresh card grading or human gold.

The bounded methodological review found this defensible because card assessment is a separable completed checkpoint preceding selector execution, and neither the candidate nor acceptance rules are being tuned to its scores. The failed source submission is excluded. All 48 source assessments and all 32 answer assessments are collected fresh. Required quality comparisons remain unchanged. Confirmation still requires untouched new tasks and pools with all reference assessments fresh.

A new source qualification, protocol, manifest, admission, clock and lease bind this stage. Earlier time and authority receive no credit, and the earlier failed call stays in resource history. There are no new development searches or source fetches. The frozen public-document inputs and complete capture inventory remain unchanged; short evidence labels still decode exactly to original references. Record identity fields remain original.

See the [protocol](evidence/EXP-089/protocol.json) and [production acceptance checklist](complete-pool-production-acceptance.md). This is an ongoing experimental study, separate from production implementation and the mainline GroktoCrawl deployment. No research-usefulness improvement is claimed.
