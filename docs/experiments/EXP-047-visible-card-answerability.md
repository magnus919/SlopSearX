## Independent reviewer contract

Run two fresh GPT-6 Luna pinned reviewers with no conversation-history fork. Give them only this review contract and the frozen blinded packet; do not provide the protocol's historical motivation, provider outcomes or sealed references. They work independently, without messaging each other, browsing, scraping, external/provider/search calls, or writing repository files. Their only output is a local structured review artifact.

For each case, answer:

1. `answerability`: `answerable` or `insufficient_visible_evidence`. Can the supplied cards support a comparison of this exact whole-set replacement for the supplied purpose and facets, without asserting unseen page contents or truth? A visible bibliographic lead can be useful without establishing what the full paper proves.
2. `judgment`: `better`, `equivalent`, `worse`, or `undecidable`. A better set adds useful visible support while preserving useful support for every requested facet already supplied. `undecidable` is required when answerability is insufficient. An answerable negative/keep judgment is distinct from uncertainty.
3. Bounded rationale (at most 250 words), referencing specific opaque IDs and visible card text. Identify any gained/lost supported facet and any assumption the cards cannot establish. Do not invent source quality, independence, authoritativeness, identity equivalence or hidden content. Report possible duplicated-publication identity as uncertainty unless supplied metadata establishes it.

The frozen trusted review contract and blinded packet each have SHA-256 fingerprints. Before invocation, validate full membership, maps, source hashes and consistent before/after sets; reject rather than repair a packet over 200,000 UTF-8 bytes or 30,000 whitespace-separated words, or a contract over 16,000 bytes. These are conservative workload guards, not a verified model tokenizer/context guarantee. If complete packet acceptance or complete review output cannot be verified, retain the diagnostic as incomplete; do not truncate, split, substitute, or use a partial review as a complete one.

Each reviewer returns exactly one JSON object with keys `schema`, `reviewer_id`, `packet_sha256`, `contract_sha256`, `cases`, `execution_attestation`.
