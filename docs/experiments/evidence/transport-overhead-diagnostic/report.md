# EXP-073 local transport-overhead diagnostic

The single prospective sample completed all 24 preregistered paired operations. It made 0 provider calls and 0 search calls; the child environments contained no provider credentials, and the only exchanges used the explicit neutral offline fixture. The sample used CPython 3.14.7, httpx 0.28.1, httpcore 1.0.9, and anyio 4.14.1. The full machine-readable results and retained raw synthetic receipts are in `results.json` and `attempt-receipts/`.

The paired median whole-phase time was 189.220 ms for cold subprocess calls and 9.267 ms for the in-process wrapper fixture path, a median paired difference of 180.033 ms (nearest-rank p95 difference 225.096 ms). Cold phase p95 was 235.944 ms; in-process phase p95 was 10.764 ms. Across 48 calls per arm, median call wall time was 92.328 ms cold and 1.251 ms in-process. Wrapper-reported local fixture exchange medians were 0.386 ms and 0.402 ms, respectively. Every pair produced byte-identical request and response hashes, and the same candidate-order digest. The sample recorded 48 cold child processes, 48 in-process calls, and 96 offline fixture exchanges.

The frozen rule is met because the median paired phase difference exceeds 100 ms. This motivates a separate, preregistered study of the production transport path if that question remains useful; it does not establish a production bottleneck or authorize a code change. The cold arm combines process startup, interpreter imports, wrapper setup, pipes, parsing, and durable receipt work. This diagnostic cannot isolate those costs. It does not estimate provider latency and supports no ranking-quality, relevance, or adoption claim. No timing was subtracted from the earlier EXP-073 result.

The production lifecycle is summarized in [the source-pinned audit](../EXP-073/production-path-audit.md): the service retains its provider object, does not start a subprocess per rerank, and creates/closes a new `httpx.AsyncClient` per call. This diagnostic's in-process `urllib` fixture arm is not a benchmark of that production client lifecycle, TLS, or connection reuse.

The earlier failed attempt is recorded in `setup-failure.json`. It completed the pair-0 cold arm, then failed in the in-process arm because an empty token triggered the wrapper's credential-echo guard. Its temporary receipts and exact timings were not retained; those values are excluded from this sample. The corrected run preserved all 144 receipt files (48 operation directories) and completed once without retries.
