# Source-use pilot outcome

The candidate ordering did not improve task completion in this two-task diagnostic pilot. Reviewer 1 judged neither arm complete on either task; reviewer 2 judged both refactoring arms complete and both flaky-test arms incomplete. This is advisory evidence from exposed tasks, not selector qualification or production readiness.

The capture accepted 22 of 28 sources. Six returned barrier errors; no page was retried. All four answer contexts contained five successful sources, with shared source bytes preserved. All 29 owned HTTP response hashes were checked. Eight planned Luna turns completed. The controller made no search, Brave or Jev calls; internal service activity was not fully observed. Capture runtime and pinned local consumer projection are different revisions, recorded in the capture receipt. Model aliases do not establish immutable model checkpoints.

*Reviewer 1's candidate correctness assessment contains one grading quotation unbound to a valid delivered answer claim. It remains an attribution failure, not qualified evidence for a facet gain. The reviewers' apparent facet improvements concern different facets and do not replicate.

Reviewer 1 required more detail about collecting diagnostics after persisted edits and defining validation scope; reviewer 2 accepted the bounded documentation workflow. Both found the flaky-test answers incomplete, including unsupported extrapolation from reproduction or targeted validation to broader regression assurance. These disagreements remain visible; no consensus gold was manufactured.

The source assessors also differed. Reviewer 1 supplied 60 valid quotations; reviewer 2 supplied 33 valid and 18 invalid quotations, so the second source assessment failed whole-assessment validation. Seven answer quotations failed exact-substring checks. Invalid links receive zero evidence credit. No outputs were repaired or regenerated. Exact matching establishes attribution, not entailment or method effectiveness.

The structured outcome distinguishes evidence in an assigned context but unused from evidence available only in the pooled source union and never delivered to that arm. The latter is a selection/delivery exclusion, not an answer-generation failure. Neither category alone establishes adequate evidence for task completion.

The retained initial setup failure made zero source attempts. Source assessments preceded answer generation, but their hash receipt was created after the first two answerer invocations; their contents were unchanged. Answer hashes and the randomized grading packet were frozen before answer grading. The answerers used a controlled structured format, not the exact production Q&A response format.

## Consequence

EXP-072 remains rejected and no selector qualifies. Before another model comparison, test an immutable evidence-ID/offset catalog to avoid asking models to reproduce quotation formatting, and define observable task checks that distinguish previews from persisted-edit diagnostics and targeted reproduction from broader regression validation. These are proposed process improvements, not demonstrated utility gains. Preserve the existing quality gates. Any final confirmation still needs new tasks and new pools.
