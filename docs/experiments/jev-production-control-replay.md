# Offline Jev production-control replay seam

`tests/jev_replay.py` is a test-only adapter for exercising a frozen, already-canonical pool through the existing `SearchService._rerank_results` and production `JevReranker` parser. It requires independent expected SHA-256 receipts for both the generated request body and archived response bytes. The response digest is checked before calling the service/parser; a mismatch raises `ReplayIntegrityError` and the parser is never invoked. The request digest is checked by the local fake transport before it exposes the archived response. Because the production reranker intentionally catches transport/parser failures and returns fallback, the adapter checks the observed request receipt after that call and raises `ReplayIntegrityError` on mismatch rather than labeling it a successful replay.

A successful replay covers only request projection, response parsing, first-40 permutation, unchanged tail, stable ties, exact result identity, and metadata preservation for supplied synthetic/frozen inputs. Tests cover 2- and 45-result pools plus malformed answer membership fallback. They use a local fake `httpx` namespace; no provider call is made.

This seam does **not** establish live acquisition, scope routing, grouping/deduplication equivalence, cache/snapshot behavior, portal/MCP projections, or deployment W0. HTTP errors, timeout behavior/timing, provider-absent specialist promotion, and keyless branches are outside this successful-response replay. It does not assess ranking quality or adoption, qualify any source receipt, or authorize a new live candidate. No runtime ranking code or scientific gates are changed here.
