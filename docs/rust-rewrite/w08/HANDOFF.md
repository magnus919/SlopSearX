## Native interfaces

`ssx_application::composition::SourceResolver` resolves the exact allowed source/destination matrix. It has snapshot, retained workflow, entity, current authority and clock ports. It has no dispatch, persistence or TTL-renewal port. `Authority::current` must return the trusted current principal's tenant together with current operator policy and staged/report bounds. Implementations must not derive authority from a tool argument or retained artifact. Policy, tenant, accumulated engine/grant witnesses and relevant bounds are rechecked after every awaited read and before return.

`ssx_application::dependency_dossier` implements package/repository normalization, exact canonical workflow digest, bounded plans, source-bound idempotency comparison, complete admitted-evidence attribution and reports. Report card limits never alter the underlying snapshot or the evidence used for name/version resolution. A supplied native card projection determines presentation; the application does not depend on MCP registry or protocol code.

`ssx_infra::dependency_dossier::DossierService` creates and reads durable jobs. Its `DossierJobs` port delegates production create/load exclusively to the existing `ResearchStore`; the narrow seam permits an exact post-persist/pre-return fixture barrier. `DossierService::runner(existing_runner)` attaches `NativeSourceValidator` to the existing W02 worker. This concrete construction path is exercised by the private-Valkey/loopback suite. Final workflow transports must use this composition instead of constructing a composed-job runner without the validator.

## Source authority at dispatch

Composed work is re-resolved before each new reservation and again after reservation/load/renew awaits immediately before search admission. Missing, null, malformed, tenant-inaccessible, expired, revoked or altered descriptors fail closed. The concrete validator compares the complete stored descriptor, including selected result IDs, query and selected-attempt/cursor details. A runner restarted without a source validator denies composed jobs. Uncomposed jobs retain the existing path.

Pre-reservation denial records failed pending queries and `source_rejected: <code>` with zero reservation and zero adapter requests. A source revoked after an acknowledged reservation records an exact failed attempt, no response/cursor/admitted results, and `source_rejected_before_dispatch: <code>`; actual adapter requests remain zero. W01's already-persisted reservation is conserved. The legacy `workflow.budget.used_adapter_calls` name records reservation exposure and must not be reported as measured actual provider calls. No refund transition was added. Read-only source admission observes worker cancellation, shutdown, the persisted deadline and a 30-second maximum resolution window. Successful validation is a dispatch-admission witness, not a promise to atomically revoke an already in-flight provider request.

## Bounds and unavailable states

Source result IDs are capped at 25; a research destination rejects a truncated seed. Research manifest sources stream the retained attempts/cursors under the existing authoritative 4 MiB durable JSON read bound; a valid 101-cursor source remains supported. Request cancellation and the worker's admission deadline bound work independently from the 25-ID output cap. Dossier query count, adapter reservations, admitted results and per-read card limits remain independent. Package attribution requires schema-v1 package payloads with the matching engine and adapter-supplied (not inferred) name. Repository metadata supplies candidates only; ownership remains false, and advisory applicability remains `not_evaluated`.

Snapshot missing, logical expiry and unavailable states remain distinct. Saved reports use their historical observation window, reject truncation before incomparability, and do not invent an expiry field when the W00 store naturally reports a missing item. Staged sources require the selected attempt and its captured cursor. Research sources retain attempt filtering, unique bounded result IDs and partial/truncated status.

## Worker authority and final transport construction

The current-principal authority port must outlive an individual request safely. A worker must not keep raw client credentials or depend on an expired request-local context. W09 must select a trusted resolver/service scoped to the leased job's tenant (or a trusted per-tenant resolver factory) and obtain live operator/principal-to-tenant authority across restarts and replicas. The stored job tenant is a lookup scope, never a grant. There is no fallback that treats a job/source descriptor as tenant authorization. A `NativeSourceValidator` configured for tenant A explicitly denies a job leased for tenant B; final multi-tenant routing remains W09's composition responsibility. The single-tenant private fixture proves this fail-closed behavior and does not certify production multi-tenant worker routing.

## Review corrections before final qualification

Independent review identified that W07 `NativeRecords::reports` intentionally returns only a lineage projection. W08 now uses a separate `SavedReports::selected` port for the complete authoritative retained row. Its native adapter delegates to `SavedStore::recent_report`; it preserves current membership, definition binding, logical expiry and unavailable states without changing W07. The owning read receives an immutable catalog/policy restricted to the intersection of current operator and principal eligibility, including sensitive-engine policy. This prevents an internally re-read definition from changing to an engine that only the operator may access. The selected historical window and every eligible scope used for the read are revalidated before disclosure. A controlled operator-only policy mutant demonstrates that race; an unchanged allowed definition still resolves under an unrelated principal restriction.

Resolution carries the earliest known logical expiry through subsequent awaits and the final synchronous witness. Snapshot expiry preserves F13's strict comparison; staged definitions and saved definition/report expiry preserve their owning stores' inclusive comparison. Research execution deadlines are not invented as retention expiry. A saved row that its owner naturally reports missing remains missing. Tests advance the trusted clock during selected-snapshot reads and across research cursors while the newly read snapshot remains valid, so an earlier expired artifact cannot become a source.

Additional native cases exercise exact research-attempt selection/missing attempts, actual missing/expired/unavailable dossier section reads, and a blocked read-only validator under shutdown, durable cancellation, projected deadline and lease-owner loss.
