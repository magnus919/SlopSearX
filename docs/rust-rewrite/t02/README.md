# T02 native HTTP boundary

The native router reuses the accepted SearchService/Pipeline, O01 telemetry and
one startup config/policy/catalog snapshot. It supports GET and form POST on `/`
and `/search`, JSON, YAML+Markdown, CSV, RSS, functional public HTML, OpenAPI,
passive `/health`, `/healthz`, `/config`, `/metrics` and request-ID middleware.
Publication timestamps and parsed URLs are derived at the actual HTTP boundary.
Ordinary HTTP never acquires a sensitive-source grant from MCP specialist grants.

Run `cargo build --locked -p ssx-http --example t02_fixture` followed by
`cargo xtask check T02 --output target/rust-evidence/T02.json`. The gate invokes
only Rust executables. It requires exact native test identities and 421 distinct
completion bindings:270 original source HTTP,9 review HTTP,27 fault/cache,24 synthetic date-proof,
20 literal-family,2 HTML theme groups,51 pure formatter,16 pure Accept and2 pure
formatter controls cross-bound to original review HTTP null publication dates.
It validates whole responses, process identities, dispatch counts and cleanup,
rejects missing/duplicate/extra/changed bindings and missing wire receipts, then
actually omits one source case and requires failure with269 completions and a
joined server. The report embeds full raw wire receipts and HTML streams.

The supplemental native theme browser smoke exercises the served Rust HTML over
HTTP in a real Chromium instance. It checks configured defaults, valid stored-theme
overrides, invalid stored-value fallback, reload persistence, storage-access failure,
accessible button state and the painted body background. It is additional evidence;
it does not rewrite the 421 primary bindings, 352 positive receipts or 269 omission
receipts above. The client is wire-only and CI starts the fixture process separately.

`original-bindings.json` maps162 original nodes and733 literal assertions to
T02 evidence or explicit ownership. The original test bodies each completed
setup/call/teardown once in the isolated reviewed reference fixture. Full source
wire bytes, headers and body hex are under `oracle/`; the119-case stream is split
into byte-identical sub-500KB chunks. `source-provenance.json` retains literal
producer/manifest/source/input/environment/guard/cleanup identities. Python
reference producers remain temporary evidence tools and are never gate/runtime
dependencies. Reference HTTP captures use a counted synthetic source adapter;
no provider, paid, production or real source engine call is included.

Three positive page values beyond the accepted F05 u64 domain intentionally
return400 before dispatch; see `intentional-page-boundary.json`. Canonical U+FFFD
payload roundtrip is tested; raw lone-surrogate ingestion is an F05 typed-value
boundary. Synthetic date proof is not actual OpenAlex integration and cannot
close #984. T03 owns full browser/visual fidelity and its two mapped journeys.

`crates/ssx-http/Dockerfile.t02` and the dedicated image workflow qualify the same
offline native router/service fixture with an independent compiled Rust client.
The final image must have no Python executable, matching Python/PyPy symlink,
libpython or Python backend fallback; the client sends22 requests and joins the
server child under network-none, read-only, nonroot constraints. A Dockerfile or
compiled client is not image execution evidence. Actual published-head image CI
is required before image acceptance. Production assembly belongs O04 and later
cutover/release gates; the main deployment remains unchanged.

`qualification-checkpoint.json` retains earlier passes, failures and limits.
Formal final acceptance uses the subsequent stable-tree T02 report and exact-head
CI evidence, reviewed by the parent task. No source failure has been relabelled
as a passing oracle and no original assertion was relaxed.

`review-findings.json` records the three independently confirmed corrections and
the9-case source capture: malformed offset colons, category metrics after label
mapping, and final duplicate query selection for landing/search metrics. Native
checks compare the full snapshots and require the landing snapshot unchanged.
