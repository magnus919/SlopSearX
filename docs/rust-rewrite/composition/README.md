# Native research worker bootstrap (33 real factory bindings)

This component adds `ssx-worker research` using the accepted Rust SearchService, durable research runner, Valkey cache/snapshots/store and shared adapter HTTP/admission ports. It is an additive step toward [W08](https://github.com/magnus919/SlopSearX/issues/914) and [W09](https://github.com/magnus919/SlopSearX/issues/915); neither issue is complete. The foundation `ssx-server` executable, HTTP/MCP/gateway/portal startup and other worker roles are unchanged. No backend Python process is used by this worker.

Build `cargo build --locked -p ssx-worker --bin ssx-worker`. Copy [native-research.example.json](native-research.example.json) to an operator-owned config location. The complete51-entry example enables only npm and explicitly disables50 others. Review the enabled engines before starting: this component fails before store IO if any configured enabled engine has no real mounted factory. It never silently disables missing engines. The example is not a production deployment recommendation or a request to contact a provider.

```sh
VALKEY_URL=redis://127.0.0.1:6379/0 target/debug/ssx-worker --config /etc/slopsearx/native-research.json --check-config research
VALKEY_URL=redis://127.0.0.1:6379/0 target/debug/ssx-worker --config /etc/slopsearx/native-research.json research
```

`--check-config` checks configuration/policy/availability and URL grammar without opening the store or claiming readiness. Supply a real accessible Valkey only for actual operation. Config is captured once: defaults, one JSON/YAML file read, then ordered OS environment overrides. Native `observability` controls are accepted typed operator configuration; their source compatibility limits remain explicit. Keep secrets outside checked-in profiles; do not put credentials into command-line arguments or diagnostic output. `MCP_GRANT_RESEARCH` overrides the file research grant; the shared uniform sensitive grant is separate. Registering a factory does not enable it or authorize acquisition.

The mounted33 are npm,crates; brave,wikipedia,reddit; pypi,rubygems,dockerhub; github,huggingface,stackexchange,hackernews; ashby,greenhouse,lever; clinicaltrials,europepmc,pubmed,pubchem,uniprot; edgar,fred,openfda,oyez; openlibrary,musicbrainz,tmdb,nominatim,internetarchive; abuseipdb,greynoise,otx,urlhaus. Their engine-specific settings/credentials use existing typed resolvers and the same shared HTTP/admission owners. Runtime generation identity is stable across equivalent effective configuration and changes with relevant configuration/credentials. Admission denial state, real search health and existing fail-closed policy remain authoritative. Sensitive/mixed scope checks are not bypassed.

Readiness means each actual research task has entered after startup; it does not promise a successful first claim, provider call or completed job. On Unix, SIGINT/SIGTERM handlers are installed before resource-opening startup and request owned task drain. Windows supports the existing Ctrl-C branch; equivalent Unix signal behavior is not claimed. The runner retains authoritative claim/renew/reservation/snapshot/publication behavior. Search/telemetry/store close paths are awaited. Complete Redis driver ownership/join remains a separate F07 follow-up; this document does not claim its completion, OS-family absence, an all-legal-payload memory bound, or end-to-end production readiness.
