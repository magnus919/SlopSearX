V2 successor: an independent review found that session DELETE could trigger OAuth refresh or interactive authorization after EOF/SIGTERM. OAuth admission is now cancelled before cleanup; DELETE uses only the last in-memory bearer and cannot call credential/refresh/authorization helpers. HTTP, callback, browser and file owners still drain, and denied DELETE remains a reported cleanup failure. A new unexecuted actual-process matrix covers 401 and 403 insufficient_scope under EOF and SIGTERM, each with a valid and an expired bearer, an enabled private browser spy, exact auth/refresh/DCR counts, unchanged token file and child/browser/callback retirement.

All five generated .cargo-ok members are excluded from the source composition. Complete package membership and canonical digests are regenerated for httparse, hyper, hyper-util, reqwest and rmcp; archived .cargo_vcs_info.json and all runtime source bytes are retained. The source-bound gate rejects extra/missing vendor members, symlinks and special files before Cargo dispatch. This proposal does not execute the new regression or qualify global default consumers.


V3 successor: cancellation POSTs are now explicitly marked ExistingBearer by the transport owner, along with session DELETE. The HTTP/OAuth layer therefore cannot acquire OAuth.manager, inspect credential state, refresh or authorize while a retained original exchange is suspended holding that lock. The original exchange remains owned until its cancellation notification completes. A new unexecuted actual-process matrix holds a real OAuth challenge at its second callback, then exercises RPC cancellation plus EOF, direct EOF and SIGTERM against denied cancellation POSTs. The explicit-cancel variant requires a new normal RPC to acquire the released OAuth manager and complete before EOF/global cancellation, without completing the held callback. The V2 and V3 private outcome futures catch unwind panics and defer reporting until the real child, stderr reader, loopback fixture and temporary directory have been retired. Accepted V2 packaging remains byte-identical: 415 vendor members, five generated-marker omissions and their complete package digests.
