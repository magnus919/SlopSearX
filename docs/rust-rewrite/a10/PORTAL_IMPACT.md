# A10 portal impact

The five engine identities already exist in the shared catalog. A10 adds native implementations and factory bindings; it does not add a Python engine, a new browser route or a new portal field. Normalized results still use the shared domain model and existing search/storage consumers.

Browser-visible differences can arise when native production composition adopts these adapters: the finite F05 representation refusals, exact diagnostic text and native API User-Agent are documented in PARITY.md. No filter is newly claimed as enforced. Categories, specialist policy and sensitive-engine admission remain owned by their shared catalog and policy layers.

The actual native factory and storage-consumer fixtures establish this lane's adapter boundary. They do not prove a production portal or complete MCP registry mount. W09 must compose and qualify the complete native workflow, including the portal contract and browser gates. Existing required portal checks remain required for publication. This lane makes no deployment claim.
