# Actual Semantic Scholar runtime component

`semantic_runtime::register` supplies the real registry factory. HTTP, raw response ownership, same-root SourceJSON parsing, `semantic_projection` and response assembly run inside one existing RawOperation lifecycle lease. The JSON path never calls the Atom helper, opens an executable, reserves a parser-process slot, or creates a child quota. Actual factory tests use a nonexistent helper and assert the child slot stays available while operation admission is held.

The caller root is 512 MiB. Configured finite positive timeout bounds direct operations after admission; a direct call waits for admission before that timer starts. Caller SearchContext bounds admission and the complete operation; the network timeout is intersected with it. Nonfinite configured timeout requires a finite caller context, and nonpositive timeouts return Timeout. This bounded whole-operation policy differs from source HTTPX per-request timeout behavior and is not exact timeout parity. Operation shutdown and caller future drop remain observable during HTTP, JSON work and cooldown persistence. Paused Tokio controls prove parent-supervisor timing only; real-clock CPU cancellation/deadline controls remain separate.

Six immutable corpora select 183 unique IDs: 160 complete original outcomes and engine-owned request traces, 22 previously accepted typed output refusals, and one explicit source/native transport diagnostic difference. The manifest binds exact ordered IDs per class and complete corpus SHA256 values. Tests use actual result media guards, not a hardcoded media field alone. Legacy Semantic row parser is used only in tests to identify the existing refusal policy; actual runtime invokes only the bounded projector. The source config matrix is not yet part of this actual-runtime corpus selection; its dedicated seam evidence remains separate and actual integration follows.

The Retry-After implementation is engine-local compatibility code derived from the original `engines/semanticscholar.py::_parse_retry_after`, pinned Python email.utils behavior, and the existing `ssx-application/src/retry_after.rs` operation sequence. It uses borrowed fixed stack token descriptors, cooperative full input scans, static accepted Unicode16 decimal/digit-extra data, and accepted borrowed full casefold. A narrow borrowed scalar entry reuses the exact charged float implementation; the Text wrapper is unchanged in behavior. 49 original source-helper controls include all actual 429 inputs and bind exact IEEE754 delay bits; actual persistence tests compare those bits independently of rounded error wording. Full casefold's cold immutable table initialization retains the previously accepted shared-process startup overhead limitation. Consolidate the engine-local API into a reviewed shared bounded helper later without changing existing shared callers during this slice.

Raw body capacity and visible response header bytes are charged after F08 transport handoff; borrowed header descriptors and joined Retry-After output are separately charged. This is not a bound for HeaderValue backing, pooled/cookie/header allocations, synchronous URL parsing, URL normalization, or earlier transport peaks. Shared F08/G02 ownership and final public response/flight/cache lifetime qualification remain open. URL parser behavior and transport exception text have explicit source/native identity differences; no broad HTTPX URL equivalence is claimed. Existing bounded FloatNormalizer final conversion remains a synchronous CPU boundary.

Temporary offline source invocations and captured JSON are evidence only. No provider calls or Python runtime fallback exist in native paths. G08 must retire executable Python evidence tooling with the legacy backend; captured native goldens remain. Overall A06, OpenAlex/#984, HTTP/MCP/portal/cache integration, main union/inventory reconciliation, GNU/platform/resource gates remain outstanding.
