# Native scholarly qualification

The three registered scholarly factories execute Rust implementations. arXiv uses
the owned, supervised native Atom helper; Semantic Scholar and OpenAlex use the
bounded SourceJSON path without requiring an executable helper or reserving a
parser process. All reuse caller-owned admission, HTTP, deadline and shared root
budget/lifecycle handles. `ScholarlySettings::from_resolved` connects F06 YAML and
environment values to those factories without enabling engines or changing the
catalog's selection policy.

Run the required native qualification from the repository root:

```sh
cargo xtask check A06 --output target/rust-evidence/A06.json
```

The gate executes actual factories, raw Atom framing/lifecycle, source codecs,
projection and ordering, private-loopback cancellation/shutdown, private Valkey
admission/cooldown/F14 composition, and native resource launcher controls. It
requires exact completed native test identities and exact completed source-case
identities after their assertions and cleanup. Missing, duplicate, extra,
malformed or ignored evidence fails. A real skip-one-case mutation demonstrates
that a passing Rust test cannot substitute for the missing source completion.
`coverage.json` pins the relevant source bodies and immutable captures;
`completed-source-cases.json` names the claimed executions and exceptions.

The current local qualification inventory has 293 native test identities and
1,619 completed source events. The coherent-clock/readiness checkpoint before
the A09/W06 main union had 276 native identities. The earlier pre-A08-union
packet had 211 native identities and 1,535 events. These are scoped identities, not a claim that every
artifact row executes. The 41 original local regression mappings remain distinct
from conservative crosssurface discovery and unqualified handoffs. Source-only
observations, F06-unreachable null/list/map configurations and the raw header
F08 cannot represent are classified explicitly. Review and qualification must
bind the final merged source; a historical successful report is insufficient.

Original observations are immutable. Reviewed differences include finite native
whole-operation policy, typed resource refusals, native transport diagnostics,
Expat-version malformed-input corrections and the versioned native default
User-Agent. Those differences are not exact source parity. Request/session
User-Agent overrides retain precedence. Source default identity is not copied
into native runtime and the native identity is not evidence of provider uplift.

The resource verifier requires the actual expected negative exit codes, owns
fork-child kill/waitpid cleanup and checks the unchanged native allocator/FD/
NOFILE/CPU/GNU-address-space probe. Darwin evidence does not establish GNU or
absolute RSS qualification. Opaque F08 transport backing, cold shared Unicode
initialization and inherited synchronous conversion boundaries remain documented
in the component ledgers; bookkeeping is not a process-wide memory guarantee.

Native runtime and this gate never execute Python. Temporary offline source
producers and original backend tests remain inventoried under A06/G08 until
retirement; immutable captured JSON remains native input. This does not claim
that all repository CI is Python-free.

## Deadline qualification boundaries

Production uses one System monotonic clock through context admission, scholarly
query preparation, operation ownership and HTTP deadlines. The original timeout
anchors remain unchanged. A positive one-millisecond configuration can legally
expire before dispatch because preparation belongs to the same operation budget.
The original MockTransport success captures remain immutable; they do not promise
dispatch under a real elapsed-time deadline.

Across the three public factories, 42 source timeout configurations run in both
direct and caller-context modes. The inventory distinguishes 84 System observed
expiry cases from 84 controlled pending-exchange policy cases. The sealed,
test-only owner cannot supply a response, replace its transport or enter parser
workers. Its clock is shared through the pre-response path; it does not qualify
post-response parsing under controlled time. Preparation-clock, transport,
response and parser negative mutations preserve those restrictions as executable
checks. The other 1,451 completed-source records retain their identities.

The A07 context fixtures prepare the actual ordinary HTTP client before their
unchanged 70/80-millisecond query anchors, with startup recorded separately and
zero provider requests. A separate cold-Default control holds the real client
builder past a context deadline for ClinicalTrials, PubChem and PubMed, verifies
zero dispatch and retained ownership, then releases and drains the worker. This
isolates context behavior without changing production cold-start deadlines.
Original failing real-clock observations remain evidence, not discarded retries.
