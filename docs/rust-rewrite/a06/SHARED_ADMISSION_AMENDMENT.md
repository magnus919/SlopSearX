# Shared scholarly admission amendment

The arXiv, OpenAlex and Semantic Scholar factories share the existing single-operation AtomPool. Concurrent engine calls now await that same permit before any HTTP work, using the already selected network deadline capped by the caller deadline. Acquisition never renews either deadline. Parsing retains the original caller operation deadline. Pool shutdown wakes queued callers, and dropping a queued future removes its waiter. The synchronous direct parser admission API remains fail-fast. No worker, concurrency, memory allowance or independent quota is added.

The existing factory outcome test also exercises three concurrently polled registered engines, exact single active transport, queued real-deadline expiry without dispatch, cancelled waiter plus surviving peer, shutdown with a still-held operation, and final permit/worker restoration. These scenarios extend one existing test identity; the original 18 outcome cases and source markers remain unchanged.

Actual current bytes must match the reviewed digest and reverse the ordered UTF-8 byte edits to reconstruct their original digest and length. Other verification routes remain unchanged. ## Admission cancellation and shutdown

An unpolled semaphore-acquire future can already own a reserved permit after the previous holder releases it. The private admission-attempt guard owns that pinned future and any delivered permit. On cancellation or rejection it explicitly drops the acquire future first, drops the delivered permit second, and only then notifies the existing drain waiter. On success the permit transfers into the existing Operation owner, whose eventual drop also notifies. This prevents a restored-but-unannounced permit from leaving pool shutdown asleep.

The existing factory test now also reserves a permit for an actually polled waiter, starts shutdown while that waiter remains unpolled, cancels it, and requires the very next manual shutdown poll to be Ready(Ok). The prior v1 code stays Pending in this sequence: no elapsed timeout is accepted as success. A separate scenario observes an actual held HTTP exchange, drops that entire engine future, then proves the queued registered peer dispatches and succeeds with peak active HTTP equal to one. No detached test task is introduced.

Waiting uses one small boxed acquire future per invocation so its destructor can be ordered before notification. This is caller/task admission storage, not another operation allowance or worker. The existing 512MiB charged payload allowance is unchanged; it is not an aggregate bound on queued task/future allocations or whole-process memory. This proposal does not increase global operation/worker capacity or claim a new global allocation bound.

The existing timeout-clock owner control polls async admission inside its panic boundary and awaits valid admission. Both caller and network use the same previously selected deadline; forbidden owner and worker entry remain asserted. This adapts two test-only callers without adding or removing test identities.
